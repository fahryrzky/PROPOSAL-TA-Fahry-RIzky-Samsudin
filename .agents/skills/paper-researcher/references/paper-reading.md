# 论文介绍
## 如何讲清楚论文

完整介绍时按以下顺序组织。

### 1. 主要信息

- 标题、作者、机构、发表时间。
- 团队人数、作者影响力、机构背景和所在国家。
- 报告可获得的引用量及来源。
- 说明论文代码是否公开；如有官方 GitHub 仓库，报告 stars 及查询日期。

### 2. Introduction

- 建议用户自己阅读原文。

### 3. Related Work

- 建议用户自己阅读原文。

### 4. Background and Preliminaries

- 如果有，根据用户是否熟悉这个领域选择是否解释。

### 3. 方法

- 如果文章是理论分析，请逐section和subsection介绍内容。
- 如果文章提出了新的网络结构，或者使用的是我目前不知道的网络，介绍文章的网络结构是什么，输入输出是怎样的，每一个结构设计的目的是什么？

### 6. 实验

- 不罗列所有指标，只总结主要 findings（实验发现）。
- 列出数据集及其来源和用途，说明是否包含人工标注。
- 说明工作涉及从头训练、微调（fine-tuning），还是仅推理（inference）。
- 只报告论文明确披露的 GPU、其他硬件和训练时间；未披露时写“论文未报告”。
- 列出重要的软件库、代码仓库、API、模拟器、云服务或实验平台，并简要解释陌生项目。
- 当关键结论依赖某张表格时，优先展示论文原表并注明表号和来源。

### 7. 外部评价与审稿人视角

先报告能够核实的公开证据，例如 OpenReview 评审、作者回复、meta-review、最终决定、复现报告或技术批评。没有找到时明确说明，不要虚构。

然后单独标注“模拟 ICLR 风格评审”，包括：

- 优点与贡献；
- 创新性判断；
- 缺点和方法局限；
- 最脆弱的假设；
- 可复现性风险。
