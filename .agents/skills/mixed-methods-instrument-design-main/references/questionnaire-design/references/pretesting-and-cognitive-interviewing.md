# 预测试、认知访谈与现场试验

## 1. 预测试不是单一步骤

Census A2 要求新工具或实质修改工具用目标范围内的回答者预测试，并指出多种方法通常互补。专家审查只能发现潜在问题，通常不能替代受访者测试。

按开发阶段选择：

| 阶段 | 适用方法 | 主要回答 |
|---|---|---|
| 概念形成 | 焦点讨论、探索访谈、资料审查 | 人们如何理解领域和用语 |
| 题面形成 | 专家审查、认知访谈 | 题是否按预期理解与作答 |
| 界面实现 | 可用性测试、路径测试 | 是否看得见、找得到、走得通 |
| 小规模现场 | pilot、行为编码、复盘 | 招募、时长、无应答、执行是否可行 |
| 版本比较 | split-panel/随机实验 | 哪个版本按预设标准表现更好 |

## 2. 认知访谈设计

使用与正式调查目标总体相符、并覆盖关键差异的参与者。样本用于发现问题，不用于估计总体比例；轮次和组成按题目风险、异质性、语言与修订收敛决定，不套固定人数。

为每个重点题建立探询目标：

- 理解：关键词、对象、时间窗和任务如何解释；
- 检索：想到了什么事件/记录，如何确定边界；
- 判断：如何估计、归类、处理例外或敏感性；
- 映射：真实答案是否能放入选项，标签是否自然；
- 可用性：是否看到说明、错误和跳转，设备操作是否顺畅。

结合 think-aloud 与回溯/并行 probes。不要用“这题清楚吗”作为唯一探询；要求受访者复述、举例、解释选择过程和未选项。

## 3. 记录与修订矩阵

逐题记录：原版本、参与者特征、观察/原话摘要、问题阶段、严重度、频率不是决定性证据、拟修订、修订理由、新版本和复测状态。

严重度可按影响分级：无法作答/改变构念；系统性误解；选项或流程障碍；措辞或体验小问题。少数关键人群出现的严重问题不能因“人数少”忽略。

修订后重新测试受影响题、相邻上下文、跳题和所有语言/模式版本。认知访谈不是一次盖章。

## 4. 可用性与技术测试

观察真实设备上的完成过程：首屏理解、滚动、点击、输入、错误恢复、帮助、返回、进度、中断续填和提交。可用性通过不代表题意理解正确；两者分别记录。

## 5. Field pilot

pilot 要覆盖真实招募、联系、同意、问卷、平台、激励、支持和数据导出。预先定义评价指标：招募/完成路径、时长分布、断点、item nonresponse、选项分布、极端值、开放题质量、跳题错误、设备/模式差异和投诉。

pilot 不能证明正式样本代表性，也不能用小样本稳定估计复杂心理测量模型。若 pilot 发现地板/天花板、题间冗余或低质量，需要结合认知证据和理论判断，不能只按相关系数删题。

## 6. Split-panel

比较版本前先定义“更好”的标准，如理解正确率、有效回答、无应答、完成时间或外部一致性。随机分配、样本量和分析计划需匹配预期差异；不能结果出来后挑有利指标。

## 7. 交付

交付预测试 protocol、招募矩阵、逐题 probes、可用性任务、pilot 指标、修订日志和未解决问题。明确标注“计划”“已实施”或“待复测”，不得把生成的计划写成已完成证据。
