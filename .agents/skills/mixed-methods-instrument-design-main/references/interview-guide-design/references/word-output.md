# 导出 Word 访谈提纲 / Export to Word (.docx)

当用户要"生成 Word 访谈提纲""出一份现场能用的提纲""做成 Word 文档"时，把提纲导出成 .docx。**全套共三份文档，命名要全程统一**（别再混用"现场版/简版/详版"等乱称）：

- **研究者版**（Markdown）：含边界声明、研究问题—访谈题映射矩阵、可信度与三角验证设计、抽样与饱和、后续清单、设计依据——给做研究的人看，**全套方法论都在这**。
- **现场详版**（.docx）：含开场白（含知情同意）→ 暖场/基本信息 → 核心题（主问题 + 缩进的追问/探测提示）→ 收尾兜底题。用于**访前准备与现场备查**。**不含**映射矩阵、可信度术语、饱和样本量、RQ 编号等方法论内容（受访者/现场不需要，反而碍事）。
- **现场简版**（.docx 或一页纸，只列主问题/主题词）：**现场主用这份**，逼自己真听不念稿（见 `protocol-structure-and-refinement.md` 第 4 节）。

口诀：**现场主用简版、详版作准备与备查、方法论只留在研究者版。** Word 导出默认产出"现场详版"；用户要"现场带的精简单页"时再生成"现场简版"。

## 做法

用 `docx`（Node）生成。skill 自带可改模板：`assets/interview-guide-docx-template.js`。流程：

1. 确认环境：`npm ls -g docx`，没有则 `npm install -g docx`。
2. 复制模板到 /tmp，按本次提纲改 `content`（标题、开场白、各主题板块的主问题与追问/探测）。
3. 运行：`cd /tmp && NODE_PATH=$(npm root -g) node <脚本>.js "<输出路径>.docx"`
4. 校验：`python3 ~/.claude/skills/docx/scripts/office/validate.py "<输出>.docx"`
5. **务必肉眼检查排版**：转 PDF→图片看一眼（中文字体、追问缩进层级、敏感题位置）：
   `python3 ~/.claude/skills/docx/scripts/office/soffice.py --headless --convert-to pdf "<输出>.docx" --outdir /tmp && pdftoppm -jpeg -r 110 /tmp/<名>.pdf /tmp/pg`，再 Read 图片。

## 模板已封装的关键点（沿用即可）

- **页面**：US Letter、1 英寸边距。中文宋体、标题黑体。
- **三层提问视觉层级**：主问题（Q1、加粗或正常）→ 其下缩进的"追问/探测"提示（灰色小字），让访谈者一眼看清哪些是主干、哪些是备用追问。这正是访谈现场最需要的版式（区别于问卷的矩阵表）。
- **板块化**：开场白 → 基本信息 → 各主题板块 → 收尾兜底题，板块间用标题分隔。
- **留白**：每个主问题后留手写记录空行（现场记笔记用）。
- **mainQ 的 note 参数 = 访谈者私用现场提示**（如"关键题，务必问到""可与文档/统计三角验证""敏感题，先常态化"）。⚠ **现场详版禁写"服务 RQ1""构念=X"等方法论术语**——研究问题/映射矩阵只留在研究者版，否则受访者一瞥见就被语域带偏（违反 SKILL.md 第 1 步雷区）。note 用低调灰，勿用刺眼红。
- **知情同意话术**：用"严格保密 + 匿名化（去标识化）"，**不写"完全匿名"**（面对面具名访谈兑现不了，见 `trustworthiness-and-sampling.md` §4）；含录音单独同意、可中止/不答、事后可撤回。线上访谈的录音同意话术变体见 `modality-considerations.md`。

## 复用 vs 重写

模板是"案例研究/关键知情人访谈"的具体实例，不是通用引擎。新提纲直接改 `content`：保留 `P/H/mainQ/probe/section` 这些 helper 不动，只换标题和各板块题目。helper 已处理好字体、缩进层级、留白。

## 与 questionnaire-design 的差别（别搞混版式）

问卷现场版用**矩阵表 + 选项框**（封闭打分）；访谈现场版用**主问题 + 缩进追问 + 记录留白**（开放叙述）。两者版式逻辑不同，别把访谈提纲做成打分矩阵。
