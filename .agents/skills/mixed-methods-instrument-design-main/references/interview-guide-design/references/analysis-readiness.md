# 带着分析目的设计提纲 / Designing with Analysis in Mind

读本文件，让提纲为后续分析铺好路。质性方法有条原则：**带着分析目的设计数据收集工具**。后续要做主题分析、案例分析还是扎根理论，会反过来影响怎么出题、怎么记录。

⚠ 边界：本 skill **不替用户做编码与分析**。这里只讲"为了让分析顺，提纲该怎么设计"。

## 1. 先认清分析方法在第几层

- 案例研究、扎根理论、现象学 = 第①层**研究取向/设计**。
- 主题分析、编码、内容分析 = 第③层**分析技术**。
两层嵌套：一个案例研究在分析阶段**通常会用到编码/主题分析**，但不止于此（还有模式匹配、跨案例比较、多源三角）。所以"做案例研究"不等于"只做编码"。

## 2. 若后续做主题分析（Braun & Clarke）

**反身性主题分析**六阶段（Braun & Clarke, 2006；2019 强调 reflexive；2022 *Thematic Analysis: A Practical Guide*）：
1. 熟悉数据（反复读转录）
2. 编码（给与研究问题相关的片段贴码）
3. 生成初始主题
4. 检视与发展主题
5. 精炼、定义、命名主题
6. 撰写报告

**对提纲的反推**：
- 主问题最好能**对应到你预期的主题维度**（若走演绎/混合编码，提纲板块可对齐既有理论框架的领域）；但别把题问得太封闭以致只能得到你预设的主题（保留归纳空间，让新主题从受访者话里长出来）。
- 多问**具体经历、例子、过程**——这些片段最好编码；空泛态度难编码。
- 注意 reflexive TA 不追求多人编码一致性（不同于强调 inter-coder reliability 的取向）——若你的研究要报编码一致性，提纲与编码方案要相应更结构化。
- ⚠ **样本量判停别套"饱和"**：Braun & Clarke 明确反对在反身性主题分析里用数据饱和判停，主张用**信息力（information power，Malterud et al. 2016）**——别在走 reflexive TA 的研究里写"达到饱和"（与 `trustworthiness-and-sampling.md` §2 取向限定一致）。

## 3. 若后续做编码（Saldaña 编码循环）

Saldaña《The Coding Manual for Qualitative Researchers》：
- **第一轮编码（first cycle）**：贴初始码——In Vivo（用受访者原话）、描述码、过程码、价值码等。
- **第二轮编码（second cycle）**：把初始码重组为类别、主题、概念——模式码、聚焦码、轴心码等。

**对提纲的反推**：想用 In Vivo 码就多让受访者用自己的话讲（少喂术语）；想做过程码就多问"先怎样、后怎样"的过程性问题。

## 4. 若做案例研究分析（Yin）

案例研究的分析不止编码，还有：
- **模式匹配（pattern matching）**：把观察到的模式与命题预测的模式比对——所以提纲要问出能落到命题上的证据。
- **解释建构（explanation building）**：逐步建因果解释。
- **跨案例综合（cross-case synthesis）**：多案例时横向比。
- **文献比较**：把案例结论与既有文献对比——理论构建型案例研究的"点睛之笔"（中文规范特别强调）。

**对提纲的反推**：每个关键主问题对应一条命题/一个理论关注点；并在映射矩阵标注该题结论用哪些**其他证据源**三角验证（呼应 `case-study-traditions.md`）。

## 5. 通用：让数据可追溯（支撑 dependability/confirmability）

- 提纲编号稳定，转录时保留题号——便于把码追回到具体问题（证据链）。
- 记录提纲的每次修订（试访后改了什么、为什么）——审计轨迹的一部分。

> 出处：Braun & Clarke (2006, 2019, 2022)；Saldaña《The Coding Manual for Qualitative Researchers》；Yin（模式匹配/跨案例）。引用前 web 核查，见 `sources.md`。
