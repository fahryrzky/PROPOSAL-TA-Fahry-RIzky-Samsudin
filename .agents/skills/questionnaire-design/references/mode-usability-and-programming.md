# 调查模式、可用性与编程规格

## 1. 模式选择

Web、移动端、纸面、电话、面访和混合模式在覆盖、成本、视觉/听觉呈现、访员效应、敏感题、路由复杂度与数据速度上不同。模式由抽样框、目标人群可及性、题目复杂度、敏感性和资源共同决定。

多模式遵循 Census 的 Universal Presentation：保持问题含义和回答任务等价，不要求逐字或视觉完全相同。任何有意义的模式改动都要分别预测试。

## 2. 自填 Web/移动端

- 采用响应式布局；关键操作键盘可达、对比度和字体可读。
- 移动端避免横向滚动、宽矩阵、拖拽排序和过小点击目标。
- 每页一题还是多题由上下文、加载、返回和中断风险决定，不设通用答案。
- 进度条仅在可准确估算路径长度时显示；复杂跳题下错误进度会损害信任。
- 不默认强制作答。敏感或非必要题提供跳过/拒答；关键筛选题说明为何必须。
- 错误提示靠近字段，说明问题和修复办法；不得清空已填内容。
- 防重复、验证码、cookie、IP、设备指纹和登录都会带来隐私与覆盖影响，采用前先评估。

## 3. 纸面

跳题应少且视觉明确；选框、编号、栏位和翻页提示要适合录入/扫描。纸面无法实时检查时，通过版式和说明预防漏答。建立双录、逻辑检查或扫描质检计划。

## 4. 电话与面访

听觉呈现要缩短句子和选项列表；必要时分支提问或提供 flashcard。明确访员可读文本、不可读代码、探询规则、纠错与拒答处理。复杂概念不能仅依赖访员临场解释；所有帮助文本标准化。

敏感题考虑自填、ACASI 或其他降低访员在场影响的方式。代理回答、多人在场和组织内权力关系需记录。

## 5. 编程规格

每题至少包含：稳定题号、变量名、版本、universe、显示条件、跳转、随机化、piping/fill、允许值、软/硬校验、错误文本、缺失代码、帮助文本、来源和输出字段。

对随机化记录分配变量和种子/机制；对 piping 保留原始值与显示值；对多选明确互斥选项；对循环题组设最大循环和退出条件。

## 6. 路径与集成测试

在发布前建立测试案例覆盖：

- 每个筛选结果、显示条件、跳题入口与回流；
- 最短、最长和高敏感路径；
- 不知道/不适用/拒答/缺失；
- 边界值、极端合法值与非法值；
- 各设备、浏览器、语言和模式；
- 中断续填、返回修改、超时、重复提交和断网；
- 数据导出、标签、编码、时间戳、随机化和派生变量。

所有路径必须到达明确结束状态，不得有死路、循环或未展示却被强制的题。

## 7. 版本与发布控制

冻结正式版本并记录发布日期、平台、语言、哈希/版本号和变更说明。上线后不得无记录改题；紧急修订需标记受影响样本和时间，评估是否产生不可比数据。保留空白实施版、屏幕截图或导出规格、测试用例和测试结果。
